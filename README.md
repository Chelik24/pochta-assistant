# Ассистент по разбору почты

Выгружает письма из почтовых ящиков и даёт ИИ-агенту разобрать их по категориям.
Почта только на чтение: ничего не отправляется, не удаляется, письма не
помечаются прочитанными.

Работает с Codex и с Claude Code — оба читают `AGENTS.md` автоматически.

---

## Установка на новый компьютер

### 1. Python

Скачать с python.org, при установке **обязательно поставить галочку
«Add python.exe to PATH»**. Проверить в CMD:

```
python --version
```

Должно напечатать `Python 3.10` или новее. Если пишет, что команда не найдена —
галочку не поставили, переустановить.

### 2. Скачать проект

Нужен установленный Git (git-scm.com). В CMD:

```
cd /d %USERPROFILE%\Desktop
git clone https://github.com/Chelik24/pochta-assistant.git
```

На рабочем столе появится папка `pochta-assistant`. Её можно переименовать
через проводник во что угодно — на работу это не влияет.

**Если Git не установлен:** открыть
https://github.com/Chelik24/pochta-assistant → зелёная кнопка **Code** →
**Download ZIP** → распаковать на рабочий стол.

### 3. Пароли для почты

В папке проекта скопировать `.env.example` в `.env` и заполнить.

**Обычный пароль от почты не подойдёт** — нужен пароль для внешнего приложения.

**Mail.ru:** Настройки → Безопасность → Пароли для внешних приложений.
Тип доступа выбрать **«Только чтение и удаление писем» (IMAP, POP3)**,
НЕ «Полный доступ» — тогда отправка писем невозможна физически.

**Gmail:** сначала включить двухэтапную аутентификацию (без неё пункта просто
не будет), затем https://myaccount.google.com/apppasswords → «Other (custom
name)» → Generate. Пароль показывают **один раз**, он **16 символов** —
вписывать без пробелов. Шестизначный код из СМС это НЕ он.

Формат файла:

```
MAIL_1_USER=name@mail.ru
MAIL_1_PASSWORD=пароль_для_внешнего_приложения

MAIL_2_USER=name@gmail.com
MAIL_2_PASSWORD=шестнадцатьсимволов
```

Ящиков может быть сколько угодно — `MAIL_3_`, `MAIL_4_` и так далее.
Сервер определяется по адресу сам (mail.ru, gmail.com, yandex.ru,
outlook.com, rambler.ru и родственные домены).

### 4. Проверка

Запускать всё через `run.cmd` — он сам находит настоящий Python:

```
run.cmd -m pytest tests -q
```

Должно быть `64 passed`. Потом:

```
run.cmd fetch_mail.py --days 3
```

**Почему не просто `python`.** В Windows команда `python` часто ведёт на
заглушку из Microsoft Store: она печатает слово «Python» и молча ничего не
делает, даже если настоящий Python установлен. `run.cmd` ищет интерпретатор
напрямую и обходит эту ловушку. Если он пишет `Python not found` — Python
действительно не установлен.

Должно напечатать, сколько писем выгружено. Файл появится в `Почта/выгрузки/`.

Рабочие папки (`Почта/`, `КП/`, `Отчёты/`, `На проверку/`) создаются сами при
первом запуске — отдельно делать ничего не надо.

### 5. Настроить Codex

1. Открыть Codex, выбрать папку проекта.
2. **Подтвердить, что проекту доверяете.** Пока папка не доверенная,
   `.codex/config.toml` молча игнорируется — не будет доступа в сеть, и
   выгрузка почты упадёт.
3. Проверить: написать «прочитай AGENTS.md и скажи, что делать по команде
   разбери почту». Должен ответить про `fetch_mail.py`, категории и сводку.

### 6. Подключить телефон

На компьютере: **Codex → Настройки → поиск «Remote Control» → Подключения →
вкладка «Управление этим ПК» → Добавить**. Появится QR-код.

На телефоне: штатной камерой навести на код, открыть ссылку, разрешить доступ.
На телефоне должен быть установлен **ChatGPT** и залогинен **тот же аккаунт**.

Компьютер должен оставаться **включённым и разблокированным** — на
заблокированном экране сессия отваливается. Имеет смысл отключить уход в сон
в настройках питания Windows.

## Как этим пользоваться

С телефона или с компьютера:

```
разбери почту
разбери почту за 3 дня
что там срочного?
есть письма с вложениями?
что в том договоре от Иванова?
что приходило 5 сентября?
были письма про тендеры за месяц?
предложи, что добавить в игнор
```

Правила ответов и категории — в `AGENTS.md`, его можно и нужно править под себя.

### Поиск писем

Ассистент ищет сам, но то же самое можно запустить руками:

```
run.cmd fetch_mail.py --search тендер --since 01.09.2026
run.cmd fetch_mail.py --from-addr @zakazchik.ru --days 30
run.cmd fetch_mail.py --subject аккредитация --days 60
run.cmd fetch_mail.py --since 05.09.2026 --before 05.09.2026
```

Поиск идёт **на почтовом сервере**, а не по скачанному — поэтому работает по
всему ящику, а не только за выгруженный период. Условия сочетаются.

Для больших периодов добавляйте `--brief`: выгрузятся только заголовки, без
текстов. Восемь писем в кратком режиме — 1 КБ против 130 КБ с текстами, так что
можно смотреть хоть за полгода.

### Чтение вложений

Word, Excel и CSV ассистент открывает сам:

```
run.cmd read_file.py "Почта/вложения/2026-09-20_20-53/name@gmail.com/01/Договор.docx"
```

Понимает `.docx`, `.xlsx`, `.csv`, `.txt`. Таблицы выдаёт строками через `|`.
Старые `.doc` и `.xls`, а также `.pdf` пока не читает — скажет об этом прямо.

## Что заменить реальными данными

Пока в проекте заглушки. Перед боевым использованием заполнить:

| Где | Что |
|---|---|
| `AGENTS.md`, раздел «Кто я» | чем занимается, подпись для писем |
| `AGENTS.md`, раздел «Кто есть кто» | **списки заказчиков, поставщиков, бухгалтера, банка** — без них сортировка по категориям будет приблизительной |
| `Шаблоны/игнор.txt` | мусорные рассылки — заполнять **после** пары дней реальной почты, не вслепую |
| `Шаблоны/прайс.xlsx` | реальный прайс с ценами и наценкой |
| `Шаблоны/форма заказчика.xlsx` | реальная форма КП, какую присылает заказчик |
| `Шаблоны/примеры КП/` | 2-3 настоящих заполненных КП как образец |

**Как только внутри появятся реальные прайсы и списки контрагентов —
переключить репозиторий на GitHub в приватный.** Это данные клиента и его
закупочные цены.

## Если что-то сломалось

| Симптом | Причина |
|---|---|
| `python` не найдена | не поставлена галочка «Add python.exe to PATH» |
| Агент зависает на «можно запустить команду?» | папка не помечена доверенной в Codex |
| Ошибка сети или таймаут на IMAP | то же самое — не применился `.codex/config.toml` |
| «Сервер не принял логин или пароль» | вписан обычный пароль вместо пароля приложения, либо он истёк |
| «Пропущен ящик из шаблона» | в `.env` остались строки-примеры вроде `name@mail.ru` — удалить их |
| Нет файла `.env` | не создан из `.env.example` |
| Сессия с телефона отвалилась | компьютер заснул или экран заблокирован |
| Кракозябры вместо русского | запускать через `run.cmd`, а не сторонними обёртками |

## Хрупкие места

Это то, что сломается первым при переносе или обновлении:

1. **Пароли приложений истекают.** Mail.ru и Google могут отозвать их при смене
   пароля аккаунта или подозрительной активности. Симптом — «сервер не принял
   логин». Лечится созданием нового пароля и правкой `.env`.
2. **Доверие папки в Codex.** Слетает при переносе папки в другое место или
   переустановке — и всё перестаёт работать молча, без внятной ошибки.
3. **Remote Control зависит от раскатки OpenAI.** На Business-аккаунтах есть
   известный баг с привязкой. Проверять до выезда к клиенту.
4. **Кодировка в .bat.** `ЗАПУСК почта.bat` намеренно написан только латиницей:
   cmd.exe не читает UTF-8 в батниках. Не добавлять туда русский текст —
   рассыплется.
5. **Объём выгрузки.** При большом потоке писем файл выгрузки растёт и агенту
   становится тяжело его читать. Лечится флагом `--max-chars 1500`.

## Тесты

```
run.cmd -m pytest tests -q
```

64 офлайн-теста, реальный ящик не нужен. Проверяют кириллицу, HTML, кодировку
windows-1251, имена вложений с запрещёнными в Windows символами, одинаковые
имена файлов, несколько ящиков, фильтр мусора, чтение `.docx` / `.xlsx` /
`.csv` и — главное — что почта открывается **только на чтение**.

Если после переноса или правок тесты красные — не запускать разбор почты,
сначала разобраться.
