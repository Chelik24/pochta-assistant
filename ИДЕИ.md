Сделано. Письма лежат в `Почта/архив.db`, докачивается только новое, запросы
идут к базе и в сеть не ходят. Сводка — одна строка на письмо вместо файла
на сотню килобайт, примерно в сорок раз дешевле по токенам. Входящие и
отправленные, поиск по теме, отправителю и тексту.

Что осталось хвостами:
- **Глубина по умолчанию — месяц.** С Денисом не проговорено, сколько ему
  нужно на самом деле. Углубляется одной командой: `mail.py скачать --дней 180`.
- **Папки кроме Входящих и Отправленных** не качаются. Спам и Архив — если
  понадобится, добавить недолго.
- **Удалённые на сервере письма остаются в архиве.** Это скорее плюс, но
  Денису стоит про это сказать: архив живёт на его компьютере и чистку ящика
  переживает.

### ✅ Поиск по почте на стороне сервера
IMAP умеет искать сам — по слову, отправителю, диапазону дат. Тогда «какие
предложения о сотрудничестве приходили в сентябре» это один запрос на три
письма вместо выгрузки трёхсот.

```
python fetch_mail.py --search сотрудничество --since 01.09.2026
python fetch_mail.py --from @partner.ru --days 30
```

Работает по всему ящику, а не только по выгруженному периоду.

### ✅ Лёгкий режим: только заголовки
Сделано дважды: `--brief` у `fetch_mail.py` и сводка из архива, которая иначе
и не умеет. Двухступенчатость работает — сначала список, потом полный текст
нужных по номерам.

### Человеческие периоды
Понимать «за сентябрь», «на прошлой неделе», «5 числа», «за последний месяц».
Сейчас есть `--дней N` и точные даты `--с` / `--по`, а «покажи за сентябрь»
агенту приходится переводить в даты самому. Он справляется, так что это
удобство, а не необходимость.

## Большой заказ от Дениса (20.09.2026)

Записано со слов. Это уже не почтовый ассистент, а три разных продукта —
имеет смысл разделить и оценивать по отдельности.

### Блок 1. Мониторинг тендеров
- находить открытые и закрытые площадки;
- раз в день отслеживать новые конкурсы по виду работ (начинаем с клининга);
- сводка: что нового, сроки подачи, кто заказчик.

**Где брать данные.** С 1 января 2025 открытый FTP ЕИС закрыт, данные отдают
через веб-сервисы с лимитом порядка 5000 запросов в час. То есть официальный
источник по 44-ФЗ и 223-ФЗ есть, но это полноценная интеграция, а не выкачка
архивов.

Коммерческие и закрытые ЭТП своего публичного API в массе не имеют.
Реалистичный путь — платный агрегатор (Контур.Закупки, Seldon, Тендерплан):
корпоративные тарифы с API начинаются примерно от 15 000 ₽/мес. Это дешевле
и надёжнее, чем пытаться скрести сорок площадок по отдельности.

### Блок 2. Расчёт стоимости тендера
- считать по рынку и по реальной себестоимости работ;
- с учётом его модели налоговой нагрузки;
- Денис даёт один разобранный тендер как образец.

Самая понятная часть и ближе всего к тому, что уже есть (прайс, форма, КП).
Ключевое: **нужен его разобранный пример** — без него модель выдумывать нельзя.
Расчёт должен быть прослеживаемым: видно, из чего сложилась цифра, а не
«итого столько». Иначе ей нельзя доверять при подаче.

### Блок 3. Проверка контрагентов
- связи юрлиц, риски банкротства заказчика;
- уточнить формулировку про «рабочие расчётные счета» — похоже на опечатку
  голосового ввода, надо переспросить, что именно нужно.

Легальные источники: ЕГРЮЛ/ФНС, сведения о приостановлении операций по счетам,
Федресурс (банкротства), картотека арбитражных дел, ФССП. Либо платный
агрегатор вроде Контур.Фокуса — быстрее, но подписка.

### Блок 4. Аккредитация на закрытых площадках «от моего имени»

**Здесь нужна осторожность.** Подача заявки — юридически значимое действие,
подписывается его ЭЦП, и отвечает за неё он. Автоматическая подача от его
имени ломает главный принцип, на котором всё построено: агент готовит,
человек подтверждает.

Предлагаемый размен: агент собирает полный пакет документов, проверяет
комплектность по требованиям площадки, заполняет формы и кладёт готовое —
**кнопку «отправить» нажимает Денис**. Это 90% работы и ноль риска.
Обсудить с ним отдельно, не проскакивать.

### Блок 5. Сметные программы (Смета.ру, Турбосметчик)

«Подключить к аккаунтам» в буквальном смысле не получится — публичного API у
них нет. Реальный путь — **форматы обмена**: АРПС (`.arp`, стандарт ещё
2000 года), XML и выгрузки в Excel. Турбосметчик прямо заявляет поддержку
АРПС и XML, у Смета.ру есть экспорт-импорт локальных смет.

То есть схема такая: он выгружает смету в АРПС или XML → агент читает,
считает, собирает → отдаёт файл обратно в том же формате. Для начала нужна
**одна реальная смета в АРПС как образец**, иначе формат не разобрать.

### Блок 6. Аналитика по КП подрядчиков

Денис соберёт папки: на каждый конкурс — коммерческие предложения от разных
подрядчиков. Это **самая лёгкая и самая полезная часть** из всего заказа:
`read_file.py` уже читает `.docx` и `.xlsx`, остаётся сложить в сравнительную
таблицу.

Что даёт: по каждому конкурсу видно, кто из подрядчиков сколько просит,
средняя и минимальная цена по позициям, кто регулярно дешевле. Это же станет
основой для модели расчёта — реальные цифры вместо выдуманных.

Требование к папкам: одна папка — один конкурс, в имени папки номер или
название закупки. Остальное разберём.

### Что спросить у Дениса
1. Что значит «рабочие раскатные счета» — расчётные счета заказчика?
2. Какие именно площадки нужны в первую очередь, полный список.
3. Разобранный пример тендера для модели расчёта.
4. Готов ли он платить за агрегатор (~15 000 ₽/мес) или ищем бесплатный путь.
5. Есть ли у него ЭЦП и на каких площадках он уже аккредитован.

### Порядок
Сначала блок 2 (расчёт) — он не зависит от внешних подписок и даёт результат
сразу. Параллельно блок 1 на официальных данных ЕИС. Блоки 3 и 4 — после,
когда первые два обкатаны.
