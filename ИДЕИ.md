## Найдено на живом запуске у клиента (20.09.2026)

Первый боевой прогон: 23 письма за 3 дня, сводка собралась, отчёт сохранился.
Что сразу видно:

1. **Несколько писем слиплись в одну строку.** Пять разных тем («защита Google,
   вход OpenAI, смена почты, GitHub, платёжная карта») ушли одним пунктом.
   Нужно: одна строка — одно письмо, с отправителем. Иначе непонятно, куда идти
   разбираться.
2. **Цифры не сходятся.** Заявлено 23 письма, в сводке видно 10 рекламных и
   несколько важных. Остальные просто исчезли из поля зрения. Нужно правило:
   сумма по категориям обязана равняться общему числу.
3. **Нет категории «Тендеры».** У клиента это основной поток — уведомления
   участнику, запросы предложений, результаты отбора подрядчика. Сейчас всё это
   падает в «Остальное» и теряется. Нужна отдельная строка вверху, со сроками:
   в тендерах дедлайн и есть главное.
4. **`.docx` не читается.** CSV агент осилил, а Word — это zip-архив, а не
   текст. У клиента основное приходит вордом. Без этого он не ответит на
   «что там в документе».
5. **Заглушки в `.env` вызывают путаницу.** Если оставить пример
   `name@mail.ru`, скрипт честно пытается войти и ругается на пароль — хотя
   проблема совсем в другом. Нужно пропускать строки, которые остались
   из шаблона, и говорить об этом понятно.
6. **В `AGENTS.md` написано «22 passed»** — осталось от старой версии, сейчас
   тестов 39. Агент может испугаться расхождения.

## Ближайшее

### Поиск по почте на стороне сервера
IMAP умеет искать сам — по слову, отправителю, диапазону дат. Тогда «какие
предложения о сотрудничестве приходили в сентябре» это один запрос на три
письма вместо выгрузки трёхсот.

```
python fetch_mail.py --search сотрудничество --since 01.09.2026
python fetch_mail.py --from @partner.ru --days 30
```

Работает по всему ящику, а не только по выгруженному периоду.

### Лёгкий режим: только заголовки
От кого, когда, тема, есть ли вложения — без текстов. Письмо занимает строку
вместо страницы, можно окинуть взглядом тысячи писем. Двухступенчато: сначала
список, потом полный текст нужных.

Сейчас потолок — примерно 150-200 писем с текстами на один разбор
(50 писем = 133 КБ). Дальше агент начинает захлёбываться.

### Человеческие периоды
Понимать «за сентябрь», «на прошлой неделе», «5 числа», «за последний месяц».
Сейчас только «за N дней назад», и сказать «покажи за 5 сентября» нельзя.

### Чтение вложений
Маленький скрипт, достающий текст из `.docx`, `.xlsx`, `.csv`, `.pdf`.
Для docx и xlsx хватит стандартной библиотеки — это zip с XML внутри.
Тогда «что там в документе» начинает работать.

## Потом

- **КП:** прайс, форма заказчика, примеры, сценарий заполнения. Неизвестные
  позиции помечать `??` и выносить в вопросы, а не выдумывать цену.
- **Черновики ответов** — показывать текст в чате, отправляет человек сам.
- **Автопредложения в фильтр мусора** — агент сам смотрит выгрузку и
  предлагает, что добавить в `Шаблоны/игнор.txt`.
- **Утренняя сводка по расписанию** — чтобы не спрашивать, а получать.

## Позже, требует отдельного разговора

- **Отправка писем от лица клиента.** Ломает главный принцип «только чтение»,
  поэтому нужен отдельный механизм подтверждения: агент готовит, человек
  одобряет, только потом уходит.
- **Telegram-бот вместо сайта.** Сайту нужен хостинг, вход, поддержка — а
  работать будет так же, как окно Codex, которое уже есть на телефоне. Бот
  практичнее: ничего не хостить, уведомления сами приходят. Но он тоже
  отправляет наружу, то есть упирается в тот же вопрос про риски.

## Что нужно от клиента

Без этого качество сортировки останется приблизительным:

- списки заказчиков, поставщиков, бухгалтера, банка, налоговой — в `AGENTS.md`;
- чем занимается и как подписывает письма;
- какие ящики вообще рабочие, если их несколько;
- через пару дней — что из пришедшего считать мусором.
