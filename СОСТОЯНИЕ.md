## Что работает прямо сейчас

Проверено вживую на обеих машинах.

### Разбор почты
`fetch_mail.py` — выгрузка писем по IMAP, **только на чтение**: ящик
открывается с `readonly=True`, письма забираются через `BODY.PEEK[]`, поэтому
остаются непрочитанными. Ничего не отправляется, не удаляется, не перемещается.
Отдельный тест падает, если эта гарантия исчезнет из кода.

Умеет:
- несколько ящиков за один запуск, сервер определяется по адресу
  (mail.ru, gmail, yandex, outlook, rambler);
- упавший ящик не роняет остальные — в отчёт идёт строка `⚠️`;
- сохранение вложений с чисткой имён под Windows, одинаковые имена не
  затирают друг друга;
- фильтр мусора по `Шаблоны/игнор.txt` — отброшенные письма не исчезают,
  а перечисляются в конце файла;
- поиск на сервере: `--search`, `--from-addr`, `--subject`;
- точные даты: `--since 05.09.2026 --before 05.09.2026`;
- `--brief` — только заголовки (8 писем ≈ 1 КБ против 130 КБ с текстами).

### Чтение вложений
`read_file.py` — достаёт текст из `.docx`, `.xlsx`, `.csv`, `.txt`.
**Только стандартная библиотека**, ставить ничего не надо: docx и xlsx — это
zip с XML внутри. Таблицы выдаются строками через `|`.

Не умеет: `.doc`, `.xls`, `.pdf` — говорит об этом прямо, без выдумок.

### Подготовка КП
Образцы под клининг в `Шаблоны/`: прайс на 20 позиций, пустая форма заказчика
с формулами, пример ТЗ, два заполненных КП. **Данные вымышленные**, заменяются
на настоящие.

Сценарий прогнан целиком: в ТЗ была дератизация, которой нет в прайсе (в прайсе
есть похожая дезинфекция — ровно та ловушка, куда легко скатиться). Позиция
получила `??`, в итог не вошла, уехала в блок вопросов. Цену никто не выдумал.

Итог проверен настоящим Excel через COM: **925 965 руб.**, совпало с
независимым расчётом на Python. Исходная форма не тронута — сверен хеш файла.

### Запуск
- `run.cmd` — находит настоящий Python в обход заглушки Microsoft Store;
- `ЗАПУСК почта.bat` — выгрузка в один клик для человека за компьютером;
- `.codex/config.toml` — доступ в сеть для IMAP и работа без переспросов.

### Тесты
```
run.cmd -m pytest tests -q
```
**66 офлайн-тестов**, реальный ящик не нужен. Если после правок что-то красное —
не запускать разбор почты, сначала разобраться.

## Грабли, на которые уже наступили

Это самая ценная часть файла. Каждый пункт стоил времени.

1. **`python` в Windows ведёт на заглушку Microsoft Store.** Она печатает слово
   «Python» и молча ничего не делает, даже когда настоящий Python установлен.
   Именно на этом встали у клиента. Лечение — `run.cmd`, который ищет
   интерпретатор напрямую. **Везде запускать через `run.cmd`, не через
   `python`.**

2. **cmd.exe не читает UTF-8 в `.bat`.** Русский текст в батнике рассыпается на
   ошибки вида `'окажите' is not recognized`. Поэтому `ЗАПУСК почта.bat`
   написан только латиницей, а все русские сообщения печатает Python. Не
   добавлять туда кириллицу.

3. **Git Bash спотыкается о кириллические пути.** Heredoc с русским текстом
   ломается, `wc` не находит файлы в папках вроде `На проверку`. На этой машине
   работать через **PowerShell**, а файлы писать инструментами редактирования,
   а не через `cat > файл`.

4. **`imaplib` не кодирует кириллицу внутри команды.** Русское слово в
   `SEARCH` просто не доходит до сервера. Решение: слово уходит отдельным
   литералом и обязано быть **последним** аргументом. Литерал может быть только
   один на запрос — второе русское условие фильтруется уже у нас. Проверено
   вживую на mail.ru и gmail, оба принимают.

5. **Забытые строки из `.env.example` ломали вход.** Клиент заполнил второй
   ящик, а первый остался примером `name@mail.ru` — скрипт честно пытался войти
   и ругался на пароль, уводя в сторону. Теперь такие строки пропускаются с
   понятным сообщением.

6. **`smime.p7s` — это не вложение, а криптоподпись письма.** На живом ящике
   все 8 «вложений» оказались подписями. Теперь отбрасываются.

7. **openpyxl пишет формулы без посчитанных значений.** Файл, собранный
   программой, показывал пустые ячейки вместо цен. Поэтому прайс и примеры КП
   содержат числа, а `read_file.py` показывает саму формулу, если значения нет.
   **Агент обязан пересчитывать суммы сам**, не полагаясь на формулы.

8. **Папка должна быть доверенной в Codex.** Пока не подтвердишь доверие,
   `.codex/config.toml` молча игнорируется — не будет доступа в сеть, и
   выгрузка почты упадёт без внятной ошибки.

9. **Remote Control живёт в приложении Codex, а не в ChatGPT.** Официальная
   документация говорит про ChatGPT → Settings → Connections, но в текущей
   сборке это **Codex → Настройки → поиск «Remote Control» → Подключения →
   вкладка «Управление этим ПК» → Добавить**. Потеряли на этом много времени.

10. **На ChatGPT Business есть баг с привязкой телефона.** Enrollment не
    проходит, выдаёт «Couldn't update remote control availability», на личном
    аккаунте на том же компьютере всё работает. Обхода нет.
    **Узнать тариф Дениса до того, как что-то обещать.**

11. **Компьютер должен быть разблокирован.** На заблокированном экране сессия
    с телефона отваливается. Имеет смысл отключить уход в сон.

12. **`.env` не открывать, не выводить, не коммитить.** Он в `.gitignore`,
    перед каждым пушем это проверялось отдельной командой.

## Что проверено, а что нет

**Проверено вживую:**
- выгрузка почты с двух ящиков (mail.ru и Gmail), кириллица не ломается;
- поиск по русскому слову на обоих серверах;
- краткий режим, диапазоны дат, фильтр по отправителю;
- чтение прайса, формы и примеров КП;
- расчёт КП и пересчёт формул настоящим Excel;
- установка с нуля на машине клиента, включая обновление из репозитория.

**Не проверено:**
- чтение **настоящего** ворда от заказчика — тесты гоняют файлы, собранные
  вручную в самих тестах. Нужно прислать себе реальный документ с таблицей;
- два правила формата сводки (одна строка на письмо, сходящиеся цифры) — это
  инструкции агенту, а не код. Видно только на живой сводке;
- сценарий КП силами самого агента, а не скриптом;
- работа с телефона у Дениса.

## Куда двигаться дальше

Полный список с обоснованиями — в `ИДЕИ.md`. Коротко, по возрастанию сложности:

| # | Что | Чего ждём |
|---|---|---|
| 1 | Аналитика по КП подрядчиков | папки по конкурсам от Дениса |
| 2 | Модель расчёта стоимости | его разобранный тендер как образец |
| 3 | Сметы через АРПС/XML | одна реальная смета в АРПС |
| 4 | Мониторинг тендеров (ЕИС) | список видов работ |
| 5 | Проверка контрагентов | — |
| 6 | Закрытые площадки | подписка на агрегатор ~15 000 ₽/мес |
| 7 | Аккредитация на площадках | отдельный разговор, см. ниже |

**Начинать с пункта 1.** Он самый лёгкий — `read_file.py` уже читает ворд и
эксель, остаётся сложить в сравнительную таблицу. И он же даёт фактуру для
пункта 2: модель расчёта надо строить на реальных цифрах Дениса, а не на
выдуманных.

### Важное про источники данных
- **ЕИС закрыл открытый FTP с 1 января 2025.** Данные по 44-ФЗ и 223-ФЗ теперь
  отдают через веб-сервисы с лимитом около 5000 запросов в час. Официальный
  источник есть, но это полноценная интеграция, а не выкачка архивов.
- **Закрытые площадки публичного API в массе не имеют.** Скрести их по
  отдельности — гарантированная боль. Реалистичный путь — платный агрегатор
  (Контур.Закупки, Seldon, Тендерплан), корпоративные тарифы с API от
  ~15 000 ₽/мес.
- **Смета.ру и Турбосметчик** «подключить к аккаунту» нельзя — API нет.
  Работать через форматы обмена: АРПС (`.arp`), XML, Excel.

### Про аккредитацию — осторожно
Денис просил, чтобы ассистент подавался на аккредитацию **от его имени**. Это
юридически значимое действие, подписывается его ЭЦП, отвечает за него он, и
площадки обычно требуют, чтобы подпись применял владелец лично.

Предложенный размен: **агент собирает пакет документов, проверяет комплектность
по требованиям площадки, заполняет формы — кнопку «отправить» нажимает Денис.**
Это 90% работы и ноль риска. С ним это ещё не проговорено.

## Как продолжить в новом чате

Открыть новую сессию в папке проекта и написать примерно так:

```

```

Агент подхватит `AGENTS.md` автоматически (и Codex, и Claude Code), остальное
прочитает по просьбе.

### Обновить копию у клиента
Промт для Codex на его машине:

```

Файл .env и папки Почта, КП, Отчёты, На проверку не трогай, там данные и пароль. Содержимое .env мне не показывай. Потом запусти run.cmd -m pytest tests -q и коротко покажи результат.

Ожидаемый ответ: `66 passed`.
