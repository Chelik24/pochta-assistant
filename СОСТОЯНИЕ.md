## Что работает прямо сейчас

Проверено вживую на обеих машинах.

### Разбор почты
`fetch_mail.py` — выгрузка писем по IMAP в markdown-файл. После появления
архива это запасной путь: нужен, когда база повреждена или письмо старее
всего, что скачано. **Только на чтение**: ящик
открывается с `readonly=True`, письма забираются через `BODY.PEEK[]`, поэтому
остаются непрочитанными. Ничего не отправляется, не удаляется, не перемещается.
Отдельный тест падает, если эта гарантия исчезнет из кода.

Умеет:
- несколько ящиков за один запуск, сервер определяется по адресу
  (mail.ru, gmail, yandex, outlook, rambler);
- упавший ящик не роняет остальные — в отчёт идёт строка `⚠️`;
- сохранение вложений с чисткой имён под Windows, одинаковые имена не
  затирают друг друга;
- фильтр мусора по `Шаблоны/игнор.txt` — отброшенные письма не исчезают,
  а перечисляются в конце файла;
- поиск на сервере: `--search`, `--from-addr`, `--subject`;
- точные даты: `--since 05.09.2026 --before 05.09.2026`;
- `--brief` — только заголовки (8 писем ≈ 1 КБ против 130 КБ с текстами).

### Локальный архив почты
`mail.py` — письма лежат в `Почта/архив.db` (SQLite, стандартная библиотека).
Старая почта не меняется, поэтому качается один раз, а дальше докачивается
только новое: по UID, с отметкой последнего скачанного письма в каждой папке.
Гарантия «только чтение» та же — readonly и `BODY.PEEK`, тест это стережёт.

Команды: `скачать`, `сводка`, `поиск`, `письмо`, `статистика`. У каждой есть
латинский двойник (`sync`, `summary`, `search`, `show`, `stats`) — русское
слово не выживает в `.bat`.

Зачем: раньше на каждый вопрос про почту заново выкачивался файл на 137 КБ,
и агент вчитывал его целиком. Теперь сводка — около 130 байт на письмо
(86 писем = 11 КБ), а полные тексты запрашиваются поштучно по номерам.
Примерно в сорок раз дешевле по токенам.

Скачиваются входящие и отправленные. Папка отправленных ищется по флагу
сервера `\Sent` — проверено на Gmail и mail.ru, у обоих она называется
по-русски в кодировке IMAP, и оба флаг отдают.

Глубина задаётся при скачивании и запоминается (`covered_since`). Попросили
период глубже собранного — архив сам добирает старое отдельным запросом
`SINCE … BEFORE …`. То есть `mail.py скачать --дней 180` на непустом архиве
работает как «хочу архив за полгода», а не «проверь новое». Обычная ежедневная
докачка за старым не лезет.

Поиск — FTS5 с `unicode61 remove_diacritics 2` (то есть «ё» равно «е»).
Морфологии он не знает: к слову дописывается `*`, а если и так пусто —
по букве отрезается окончание, и в ответе честно сказано, что искали
по основе.

### Чтение вложений
`read_file.py` — достаёт текст из `.docx`, `.xlsx`, `.csv`, `.txt`.
**Только стандартная библиотека**, ставить ничего не надо: docx и xlsx — это
zip с XML внутри. Таблицы выдаются строками через `|`.

Не умеет: `.doc`, `.xls`, `.pdf` — говорит об этом прямо, без выдумок.

### Подготовка КП
Образцы под клининг в `Шаблоны/`: прайс на 20 позиций, пустая форма заказчика
с формулами, пример ТЗ, два заполненных КП. **Данные вымышленные**, заменяются
на настоящие.

Сценарий прогнан целиком: в ТЗ была дератизация, которой нет в прайсе (в прайсе
есть похожая дезинфекция — ровно та ловушка, куда легко скатиться). Позиция
получила `??`, в итог не вошла, уехала в блок вопросов. Цену никто не выдумал.

Итог проверен настоящим Excel через COM: **925 965 руб.**, совпало с
независимым расчётом на Python. Исходная форма не тронута — сверен хеш файла.

### Запуск
- `run.cmd` — находит настоящий Python в обход заглушки Microsoft Store;
- `ЗАПУСК почта.bat` — докачка и сводка в один клик для человека за компьютером;
- `.codex/config.toml` — доступ в сеть для IMAP и работа без переспросов.

### Тесты
```

```
**115 офлайн-тестов**, реальный ящик не нужен. Если после правок что-то красное —
не запускать разбор почты, сначала разобраться.

## Грабли, на которые уже наступили

Это самая ценная часть файла. Каждый пункт стоил времени.

1. **`python` в Windows ведёт на заглушку Microsoft Store.** Она печатает слово
   «Python» и молча ничего не делает, даже когда настоящий Python установлен.
   Именно на этом встали у клиента. Лечение — `run.cmd`, который ищет
   интерпретатор напрямую. **Везде запускать через `run.cmd`, не через
   `python`.**

2. **cmd.exe не читает UTF-8 в `.bat`.** Русский текст в батнике рассыпается на
   ошибки вида `'окажите' is not recognized`. Поэтому `ЗАПУСК почта.bat`
   написан только латиницей, а все русские сообщения печатает Python. Не
   добавлять туда кириллицу.

3. **Git Bash спотыкается о кириллические пути.** Heredoc с русским текстом
   ломается, `wc` не находит файлы в папках вроде `На проверку`. На этой машине
   работать через **PowerShell**, а файлы писать инструментами редактирования,
   а не через `cat > файл`.

4. **`imaplib` не кодирует кириллицу внутри команды.** Русское слово в
   `SEARCH` просто не доходит до сервера. Решение: слово уходит отдельным
   литералом и обязано быть **последним** аргументом. Литерал может быть только
   один на запрос — второе русское условие фильтруется уже у нас. Проверено
   вживую на mail.ru и gmail, оба принимают.

5. **Забытые строки из `.env.example` ломали вход.** Клиент заполнил второй
   ящик, а первый остался примером `name@mail.ru` — скрипт честно пытался войти
   и ругался на пароль, уводя в сторону. Теперь такие строки пропускаются с
   понятным сообщением.

6. **`smime.p7s` — это не вложение, а криптоподпись письма.** На живом ящике
   все 8 «вложений» оказались подписями. Теперь отбрасываются.

7. **openpyxl пишет формулы без посчитанных значений.** Файл, собранный
   программой, показывал пустые ячейки вместо цен. Поэтому прайс и примеры КП
   содержат числа, а `read_file.py` показывает саму формулу, если значения нет.
   **Агент обязан пересчитывать суммы сам**, не полагаясь на формулы.

8. **Папка должна быть доверенной в Codex.** Пока не подтвердишь доверие,
   `.codex/config.toml` молча игнорируется — не будет доступа в сеть, и
   выгрузка почты упадёт без внятной ошибки.

9. **Remote Control живёт в приложении Codex, а не в ChatGPT.** Официальная
   документация говорит про ChatGPT → Settings → Connections, но в текущей
   сборке это **Codex → Настройки → поиск «Remote Control» → Подключения →
   вкладка «Управление этим ПК» → Добавить**. Потеряли на этом много времени.

10. **На ChatGPT Business есть баг с привязкой телефона.** Enrollment не
    проходит, выдаёт «Couldn't update remote control availability», на личном
    аккаунте на том же компьютере всё работает. Обхода нет.
    **Узнать тариф Дениса до того, как что-то обещать.**

11. **Компьютер должен быть разблокирован.** На заблокированном экране сессия
    с телефона отваливается. Имеет смысл отключить уход в сон.

12. **`.env` не открывать, не выводить, не коммитить.** Он в `.gitignore`,
    перед каждым пушем это проверялось отдельной командой.

13. **IMAP на запрос `UID N:*` всегда что-то отдаёт.** Даже когда новых писем
    нет, сервер возвращает последнее имеющееся. Если это не отфильтровать,
    докачка каждый раз тянет одно и то же письмо. Отбрасываем всё, что не
    больше уже скачанного UID.

14. **UIDVALIDITY может смениться.** Тогда прежние номера писем указывают уже
    на другие письма, и архив по этой папке надо собирать заново. Метка
    хранится в базе и сверяется при каждой докачке.

15. **Папка отправленных называется у всех по-разному** и на mail.ru с Яндексом
    ещё и по-русски, в кодировке IMAP (`&BB4EQgQ,BEAEMAQyBDsENQQ9BD0ESwQ1-`).
    Угадывать по имени бесполезно — спрашиваем у сервера флаг `\Sent`.
    Gmail и mail.ru его отдают, проверено.

16. **Полнотекстовый поиск не знает русской морфологии.** `тендер*` найдёт
    «тендеры», но `заявка*` не найдёт «заявок» — расходятся не окончания,
    а буквы внутри слова. Поэтому при пустом результате слово укорачивается
    по букве, и агенту в ответе прямо пишется, что искали по основе.

17. **Русские команды не выживают в `.bat`** — это та же грабля №2, но уже про
    аргументы. Поэтому у каждой команды `mail.py` есть латинский двойник:
    `sync`, `summary`, `search`, `show`, `stats`, и ключи вроде `--days`.

18. **Рассылки набиты невидимыми символами.** Неразрывные пробелы и символы
    нулевой ширины идут в вёрстке по тысяче подряд, и на экране их не видно,
    а в тексте письма они остаются и стоят тех же денег, что слова. Чистятся
    в `почистить_пустоту()` — и в HTML, и в обычном тексте: рассылки кладут
    их в обе части письма.

19. **Номера писем должны быть стабильными.** Агент показывает их Денису
    («открой 142»), поэтому при повторном чтении письма строка в базе
    **обновляется**, а не удаляется и вставляется заново. Иначе после
    `--заново` все номера разъезжаются, и разговор с Денисом ломается.

20. **После обновления проекта нужен новый чат в Codex.** `AGENTS.md`
    прочитывается один раз, в начале сессии. Обновили файлы на диске —
    в старом чате агент всё равно живёт по прежним правилам. Поймали на этом:
    после появления `mail.py` агент отказался его запускать, потому что в его
    копии правил доступ к почте разрешён только через `fetch_mail.py`.
    Само по себе это хорошая новость — правило сработало и агент не полез
    в обход. Лечение: новый чат, первым делом «перечитай AGENTS.md».


21. **Докачка по UID вглубь не смотрит.** Запрос «новее последнего скачанного»
    по определению не увидит старые письма: у них номера меньше. Поэтому
    «скачать за полгода» на непустом архиве сперва ничего не делало и бодро
    отвечало «докачано 0». Теперь глубина хранится в базе, и за старым ходит
    отдельный запрос. **Ловушка общая: инкрементальная синхронизация молчит
    не только когда всё хорошо, но и когда спросили не то.**

- работа с телефона у Дениса;
- архив на большом ящике: 345 писем за месяц прошли нормально, на нескольких
  тысячах по времени не мерили. Смена UIDVALIDITY на живом сервере не
  случалась — проверена только тестом;
- живая сводка по команде «разбери почту» на его машине: архив собран,
  но сам разбор ещё не прогоняли. Два правила формата так и остаются

эксель, остаётся сложить в сравнительную таблицу. И он же даёт фактуру для
пункта 2: модель расчёта надо строить на реальных цифрах Дениса, а не на
выдуманных.

### Важное про источники данных
- **ЕИС закрыл открытый FTP с 1 января 2025.** Данные по 44-ФЗ и 223-ФЗ теперь
  отдают через веб-сервисы с лимитом около 5000 запросов в час. Официальный
  источник есть, но это полноценная интеграция, а не выкачка архивов.
- **Закрытые площадки публичного API в массе не имеют.** Скрести их по
  отдельности — гарантированная боль. Реалистичный путь — платный агрегатор
  (Контур.Закупки, Seldon, Тендерплан), корпоративные тарифы с API от
  ~15 000 ₽/мес.
- **Смета.ру и Турбосметчик** «подключить к аккаунту» нельзя — API нет.
  Работать через форматы обмена: АРПС (`.arp`), XML, Excel.

### Про аккредитацию — осторожно
Денис просил, чтобы ассистент подавался на аккредитацию **от его имени**. Это
юридически значимое действие, подписывается его ЭЦП, отвечает за него он, и
площадки обычно требуют, чтобы подпись применял владелец лично.

Предложенный размен: **агент собирает пакет документов, проверяет комплектность
по требованиям площадки, заполняет формы — кнопку «отправить» нажимает Денис.**
Это 90% работы и ноль риска. С ним это ещё не проговорено.

## Что нужно получить от Дениса

Блокирует дальнейшую работу:

1. **Папки с КП подрядчиков** — одна папка на конкурс, в названии номер или
   название закупки. Разблокирует пункт 1.
2. **Разобранный тендер** — он сам предложил. Разблокирует пункт 2.
3. **Одна смета в формате АРПС** — для пункта 3.
4. **Списки контрагентов** для `AGENTS.md`: заказчики, поставщики, бухгалтер,
   банк, налоговая. Без них сортировка писем остаётся приблизительной — это
   даёт самый заметный прирост качества за 10 минут разговора.
5. **Чем занимается и как подписывает письма** — для раздела «Кто я».

## Как продолжить в новом чате

Открыть новую сессию в папке проекта и написать примерно так:

```
Прочитай СОСТОЯНИЕ.md, AGENTS.md и ИДЕИ.md — там весь контекст.
Продолжаем работу над проектом.
```

Агент подхватит `AGENTS.md` автоматически (и Codex, и Claude Code), остальное
прочитает по просьбе.

### Обновить копию у клиента
Промт для Codex на его машине:

```
Обнови проект из репозитория https://github.com/Chelik24/pochta-assistant — скачай оттуда архив main.zip, распакуй во временную папку и перенеси файлы поверх текущей папки проекта. Файл .env и папки Почта, КП, Отчёты, На проверку не трогай, там данные и пароль. Содержимое .env мне не показывай. Потом запусти run.cmd -m pytest tests -q и коротко покажи результат.
```

Ожидаемый ответ: `115 passed`.

**Дальше — обязательно новый чат.** `AGENTS.md` читается один раз, в начале
сессии, и в том же чате агент останется со старыми правилами: на `mail.py`
он ответит, что доступ к почте разрешён только через `fetch_mail.py`.

После обновления архив почты на его машине ещё пустой. Собрать его — вторым
промтом, отдельно, потому что это несколько минут:

```
Запусти run.cmd mail.py скачать и покажи, что он ответил. Это займёт несколько минут, дождись конца. Потом run.cmd mail.py статистика.
```

Ожидаемый ответ: сколько писем скачано и с какой даты собран архив. Дальше
всё быстро: докачка идёт только по новым письмам.

**Если писем окажется мало или период не тот** — глубина задаётся при первой
заливке: `run.cmd mail.py скачать --дней 180`. Это тоже разовая операция.

### Если понадобится записывать КП в Excel
На машине клиента пока не стоит `openpyxl`:
```
run.cmd -m pip install pytest openpyxl
```
Разбор почты и чтение вложений работают и без него.
